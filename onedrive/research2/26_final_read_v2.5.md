13 November 2026 · reviewer: the v2.6 editor · subject: `FD_v2.5.md` (2,014 lines) · result: `FD_v2.6.md`

## 1. What was done

The v2.5 editor applied the 43 findings of report 25 but could re-read only sections 1–9 end to end. Sections 10–30, the section 21 open items and the section 18 config were checked by script only. This report is one full read of `FD_v2.5.md` from the title to section 30, including the change log, by one reader, looking for contradictions, dangling rules, undefined terms, differences between the prose and the section 18 YAML, mismatches with the section 3 interfaces, and anything a builder would have to guess.

**Coverage.** Every section was read in full: document control and "How to read"; change log CL-J, CL-K, CL-H, CL-I, CL-A to CL-G; sections 1 to 30. No section was skipped or sampled. The archive file was not re-read (its text is unchanged since v2.3; only its header was re-pointed). Research reports 17, 19, 22–25 were consulted by targeted search only, to check four facts (the S-23 misfire text, the S-27 restore text, whether any report says how a symbol freeze ends, and whether any report defines `exclude_symbols`). No earlier spec version was read.

**Rules followed.** Smallest edit that removes the problem. No redesign. No number added that is not already in the spec or the reports. No owner decision (OD1 to OD9) reopened. No requirement ID, reason code, config key, command or open item added or withdrawn.

## 2. Result

16 findings: **1 Critical, 3 High, 4 Medium, 8 Low.** 15 were edited in v2.6; 1 (R-16) was left as it is.

The Critical finding (R-01) is narrow but real: after a restore from backup the system could come back without a kill, veto or halt that the user had set since the 01:30 backup, and send that day's orders. It is fixed in BP-16.

Two of the edits fill a gap where no report gives the rule, so the editor chose the reading that sends fewer orders. The owner should know about both, although neither needs a decision before the build:

- **R-04** (how a symbol freeze ends): existing commands are given the job; no command was added.
- **R-08** (what `exclude_symbols` does): an excluded sleeve is neither bought nor sold. That means an exclusion also holds back the rule's own exit in that sleeve, which is what RSK-02 already did to each intent.

## 4. Things checked and found consistent

These were checked during the read and need no edit.

- **Prose against the section 18 YAML.** Every number in sections 4, 6, 9.1, 10, 11, 12, 13, 15 and 17 that names a key agrees with it: schedule times, the 2% hold and 1% / 10% confirming-snapshot values, DAT-02, DAT-04, DAT-10 and DAT-11 thresholds, RSK-06, RSK-11, RSK-12, RSK-13, RSK-22 (including `rearm_step`), RSK-24, RSK-26, RSK-27, the kill criteria, the cap staging, the Flex pending rules, the withdrawal buffer and lapse, the commission model, and the franking limits.
- **Arithmetic.** A$9,375 for three tranches; A$7,500 as the order size where the percentage commission takes over; the cost-table totals in section 19 and their percentages; the all-in shortfall range; the 2026–27 calendar weekdays.
- **Second-factor list.** The CLI paragraph (section 3), section 15 and the commands' own rules name the same commands.
- **Planning days.** PRT-16, PRT-20, `RunContext.requests`, the 08:10 row and EXE-12 name the same triggers (after the R-04 edit).
- **"Before G4" checks.** OPS-06 and the section 17 row list the same nine checks.
- **Milestones.** Every live requirement ID is in one milestone; no withdrawn ID is.
- **Duplicate-order paths walked by hand.** A missed login with a manual order sheet followed by a carried intent; a held sell with an order-sheet line followed by the 13:00 confirming-snapshot sell; a `NOT_SENT` intent sent at 13:00; a timeout followed by a restart. In each, the send-time quantity (target minus managed position minus open orders) and the foreign-order rule prevent a second order.
- **Exits.** Outside `KILLED`, an integrity halt, a freeze and a user exclusion, no rule blocks the rule's own sell: plan delivery (OPS-04), the minimum order (PRT-17), `HALTED_BUYS` (RSK-01), a missing distribution amount (DAT-22) and a missing vendor bar (DAT-02 case (c)) all let a transition sell through.
